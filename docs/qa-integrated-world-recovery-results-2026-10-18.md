## 3. 按需世界与人物认知

- 叶子场景内的普通对象通过既有 World Gap 审核与 Core 准入，最多 3 件可携物/地点、24 件/世界、128 条裁决。现有、受保护、私有、稀缺或有资源优势的对象不得依角色愿望克隆。缺席裁决可复用；普通对象以稳定 ID 保存。
- 明确“观察这个房间”一类概览首次可确立最多 3 个显著普通对象，保留一次性场景概览记录，重复观察不刷新。详细容器内容仍按后续互动逐步裁决；概览不自动把物品交给角色。
- NPC 自治可提出带原文引用的普通对象搜索，使用相同审核与 Core 路径。NPC 的发现先记在客观事实和其个人知识里；取得物品必须经过之后独立的 Core MOVE_ITEM。失败搜索会进入后续决策上下文。NPC 移动/放下已发现物品后，玩家只有在现场明确观察才获知同一对象。
- 玩家投影遮蔽远处 NPC 实时位置、未公开物品位置、私有环境细节、未发现证据、真相关联剧情、远处人物的身体状态以及同场人物的私有警觉目标。同场可观察的警觉状态保留，供语义证据使用。
- 旧地点“未发现”不会阻挡后来经真实行动搬入的同名物品；旧检查记录保留为历史。完整的有效时间、充分检查排除范围、容器内部历史仍未建立。

## 4. 初始装备与复合行动

- 新世界生成候选若有明确的开局持有语句，已定义却未绑定的同名物品会返回具体 initial_possessions 问题；整句没有任何对应物品定义时会要求补定义。合法的随身、容器内、穿戴和异地存放会编译为权威实体与状态。职业或过去使用经历不触发补发。含多个物品但仅部分已定义的语句仍需更完整的逐项语义审核。

## 6. 本次续行新增的闭环

- 开局遗漏修复：新增 `repairOpeningPossessionsForAction`。仅当嵌入世界定义已有物品、持有者和容器绑定，且零回合快照无任何行动历史时，或最近一次有效 Undo 前像证明物品仍由角色持有、该回合新增 Core receipt 均无物品/装备变更时，才在**原玩家行动的候选事务内**恢复。原请求的 receipt 记录修复，重放不重复，Undo 撤销整体变化。同名冲突、前像不完整及长期缺失均拒绝。隔离测试覆盖相机和胶卷及后续原动作。
- 新世界候选的显式开局持有语句逐项检测物品定义；同一句已定义相机但漏定义胶片时也会返回定向修复问题。
- 环境裁决加入房间/容器范围，容器内普通物品有稳定身份和位置，首次概览最多三项，具名再查复用既有事实。容器仅限明确原文所指、同场可检查且非他人私有或封存的对象；概览不给角色背包凭空增物。
- 明确而充分的空容器检查单独登记 `complete_empty` 范围。Core 拒绝与既有内容物、旧裁决或同地点隐藏证据矛盾的空结论；该范围之后的具名查询不得追认旧时内容。后续真实 Core 放置记录顺序，才能覆盖旧缺席。无来源的同名现物返回未决，不放宽事实校验。重复查看按当前内容显示，旧空检查仍保留为历史。
- 三 NPC 通知后阅读故障序列：通知先提交，阅读阶段超时；恢复只执行余下阅读，三人通知不重发，总耗时十五分钟。NPC 旧位置知识在另一人搬动物品后保留为历史，当前客观位置独立更新。
- 新增或扩展的定向离线文件包括 `opening-possession-repair`、`local-scene-materialization`、`initial-possessions`、`environment-gap-http`、`living-world-qa22-25`。稳定代码后的最终完整离线测试：**1520/1520 通过，148 个文件**；`npm run build` 的 TypeScript、Vite 客户端与服务端编译均通过。`git diff --check` 无空白错误，仅有既有 CRLF 规范化提示。正式存档 SHA-256 复核仍为 `119585428F0739A55865F97A1372879007BFDFC6893E10EDB42179F42B60B75C`。
