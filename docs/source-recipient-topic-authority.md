# Source addressee before named topic and Planner targets

Baseline `e39a4d4` reproduced four failures: “向林舟询问乔宁去了哪里”, “跟林舟讨论乔宁的安排” and “告诉林舟乔宁的近况” followed a Planner-supplied referent/target for 乔宁. With both people present, actual Core TALK settled against 乔宁, despite the source naming 林舟 as listener. This is an original A5/A6 authorization defect, not just a display error.

The existing contract resolver now recognizes its bounded explicit single-clause address frame before using a suggested referent. The first named listener in “向 A 询问 B” owns that role; a later query verb does not promote B to listener. Existing name binding still handles ambiguity. Multi-clause/quoted text stays with the previous stage/Semantic handling, and bare multi-person questions retain their prior ambiguity contract. No broad coreference or new natural-language router is claimed.

The contract no longer appends upstream character references as extra speech-person bindings after listener resolution. Items, places and scene objects retain their existing paths. This prevents an already rejected Planner person from returning through `target_entities`; typed audience and result-reference handling remain unchanged.
