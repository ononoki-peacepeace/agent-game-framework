# Guard read migration against another JsonStore instance

Parent `5ec89d6`, product `fa53def`: an idle `current()` / `view()` migration re-read under its own service lock, then wrote its older image after another service's canonical commit. A real temporary JsonStore preflight reproduced loss of the second service's flag and receipt. Formal baseline: both two-service cases failed, while six existing same-service controls passed. All failed reports are retained.

`SaveStorage` now has an optional internal `writeMigration(expected, migrated)` capability. JsonStore compares the entire expected validated image with the current image inside a process-local queue shared by normalized lexical current-file path. All JsonStore current writes use that queue; migration comparison and replacement therefore cannot straddle another instance's write in the same process. A false comparison triggers a fresh read/normalization, at most three times; continued contention returns 409 without saving the unconfirmed candidate. Storage failures propagate, release the queue and do not become successful migration responses. Existing stores without the optional capability retain the prior behavior.

The comparison uses the pre-normalization image because structural normalization mutates its input. Full-image comparison detects same-revision changes as well as revision increments. Queued arguments are copied at entry. A new counterexample on the first fix had eight pass / one failure: mutating a caller's object after enqueue changed the eventual saved image. That report is retained; the final version preserves the queued snapshot.

Nine focused cases cover `current` and `view` against canonical, media and same-revision writes; a migration already awaiting file replacement; late caller mutation; rename failure and subsequent recovery; and three failed comparisons followed by a successful later read. Final isolated regression: **seven files, 57/57 passed, zero skips**; full isolated build passed (session 82600). It includes existing media/canonical races, migration faults, storage, external read-cache replacement and restart recovery. The actual files are isolated temporary stores; no formal save or production listener is used.

Integrate `json-store.ts` and `service.ts` together. This is an additive storage capability, not a save-schema, public HTTP, Core commit, request identity or model-budget change. Same-path same-process JsonStore migration writes are coordinated. Separate processes, symlink aliases, external non-JsonStore writers, OS kill and general competing stale canonical transactions are **not** covered. Thus R9.3/R9.4 remain open, **97/160, 60.625% (60.63%), net zero**. Latest complete snapshot stays preceding product `fa53def` / evidence `5ec89d6` (238 files / 2371 assertions); this later product has targeted evidence only.
