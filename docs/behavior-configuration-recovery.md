# Atomic behavior configuration

Legacy System affixes previously saved each scope separately. Moving a rule cleared its entire old scope before writing the destination. A later failure could leave a partial edit, delete unrelated rules, and supply no receipt to request recovery.

`GameService.updateBehaviorConfig` now accepts a bounded `set` list and `remove` selectors. A selector may name a scope and operation; an empty selector deliberately clears all style rules. Every input and the complete resulting Save are validated before `prepareRequestCommit`, then the existing storage adapter writes one atomic image containing one revision and one receipt. There is no compensation sequence. Existing `setBehaviorConfig` and `clearBehaviorConfig` callers remain supported through this path. Calls without an ID get a fresh internal ID; callers must retain an ID to identify a duplicate submission.

Direct service requests bind the full parsed edit to the receipt fingerprint. System requests bind the exact original user text with the `behavior-config:input:` namespace. This text is supplied by the server, before semantic clarification merging; it is not taken from model-generated rules. A receipt is checked before conversational interpretation, including at `/api/system`, so a committed short correction can recover after its prior session disappears. Changed text or game identity is rejected. Replay returns the current authoritative view without another write; it does not reconstruct the old conversation or promise the original wording of the response. Non-System callers must not supply the internal source-text argument to override edit identity.

Contextual moves select the previous operation and retain prefix/suffix/tone/constraint semantics. They preserve unrelated source rules. The operation uses the existing canonical mutation lock; concurrent requests receive a conflict instead of interleaving. Configuration does not create a world turn, advance time, or replace gameplay receipts. Existing World Undo/history boundaries retain style rules and original idempotency receipts.

Evidence is in the existing ignored `framework-reliability-handoff/takeover-2026-10-20` checkpoint directory. The first fault baseline reproduces partial persistence, missing preparation/receipts and unrelated-rule deletion. `behavior-atomic-final.json` verifies 82 tests across 11 files, including temporary JsonStore/HTTP restart, response loss, schema conflict, revision conflict, concurrent requests, Undo and history. The early prefix case needed a wording correction to enter the existing legacy style router; it is not counted as an independent product reproduction.

This does not establish multi-process locking, OS-crash durability, receipt recovery after the existing 100-entry eviction limit, real-provider quality, deployment or human QA. World/global/session behavior guidance remains a separate persistence boundary. Read-time migration races remain separate work.
