## 2. 执行入口与责任审计

| 入口/模块 | 允许的职责 | 已确认断点及本轮处理 |
|---|---|---|
| HTTP / routeContext / Clarification | 交互上下文、请求幂等、补充答案 | 旧澄清存在时曾无条件拼接旧请求，即使新语义是独立目标；现由 Semantic 的 clarification_resolution 明确授权续接，缺字段不自动拼接。已有唯一名称短答案补槽保留。 |
| Semantic Entry | 唯一自由输入语义所有者，动作、约束、顺序、目标 | targets 新增可选 role，区分 audience 与 subject；既有目标保真与语义安全校验保留。缺字段兼容旧结果，不把所有 entity targets 当听众。 |
| Planner / Goal Contract | 在已确认意图内编译分阶段执行契约 | 结构化听众可越过脆弱的正文解析；仅一个交流阶段时传入全局听众，多交流阶段必须逐阶段指定，不猜分配。ID 与公开名称不一致拒绝。 |
| 单人绑定 / Freeform 对象补全 | 绑定明确对象，验证存在性 | 原始复合句提及 A、B 曾推翻已指定的单人 A；已绑定目标现在优先，未知授权 ID 不回退到正文中的另一个人。 |
| Natural Scene | 已绑定场景的言语、可观察软表现及合法提案 | Contract 现在将全体听众 ID 传入已有 Scene 输入及续写片段；仍逐人检查在场。多人瞬移、未经 Core 的离场仍被拒绝或由已有安全呈现修复。 |
| Executor / Open Goal | 依赖图、有限步数、实际证据和停止点 | 原先全计划预检会阻止合法独立叶子；现在支持已绑定、无依赖的独立阶段继续；受阻阶段不执行，依赖它的阶段不执行，不为不可完成目标擅自执行准备动作。 |
| Core / Freeform | 动作、时间、物品、发现、移动的权威结算 | 已确认动作类型与目标继续复用。现实前置条件拒绝保留；模型错误不冒充“世界规则”。 |
| Narrator / Presentation | 消费 Receipt/当前地点/实际 speech_events | 不重放行动、不改人物位置；原有观察无发现、结构化对白、事实审核和安全恢复保持。 |
| 目标控制 | 查询/取消/指定续接已持久化计划 | 与 Provider 无关，读取同一 active_goal/paused_goals，精确控制命令不再交给模型猜当前是否有目标。 |

“目标对象尚未唯一确认”来自计划准入；更底层来源包括单人 referent、代词上下文、多目标、物品唯一性、运行时 result_ref。不能把这些都当群体名单问题。合法的择一、未知、缺席和结果为空仍拒绝。恢复时同一目标形状比较现在包含绑定，防止只保留文本却换人。

### 仍存在的兼容路径

旧模型结果没有角色/听众字段时，保留现有受限的公开名称与语法补全。它不是新的语义权威，不能保证覆盖任意改写。多个交流阶段缺乏明确的逐阶段听众时，不用一份全局集合强行填充。复杂前置条件与最终目标保真仍依赖已有模型审核，未证明可完全确定性替代。

## 3. 错误恢复：只修失败层

| 类别 | 边界和预算 |
|---|---|
| 语义 Schema/不确定 | 原有最多 2 次语义尝试，先确定性修复可选 null，再传字段路径、错误类型和必要失败候选；复验完整 Schema 与语义约束。本轮关闭该调用内部额外截断重试，避免 2×2 放大。正常成功不新增调用。 |
| 传输超时/程序异常 | 没有候选可修，不因 Scene 空结果再请求一次；timeout、unknown 程序错误等终止；既有 Provider 熔断保留。 |
| 绑定 | 公开名称/权威 ID/在场状态程序校验；不因单目标歧义启动完整语义重试，也不随便换对象。 |
| Planner 契约/目标保真 | 保留已有最多 3 次、重复错误提前停止的循环；只在明确反馈指向语义所有者且尚未执行时允许既有的一次语义纠正，不无限来回。 |
| Scene Schema | 原先 sceneAgent 把所有异常吞成 null，字段和网络类别均丢失；现保留 SceneSchemaError、路径/类型/期望及受限候选，传给现有最多 2 次场景循环。去掉内部截断重试，不把场景错误送回完整规划。 |
| Scene 普通文字违规 | 先做既有程序呈现修复，重新检查；必要时仅重生成该阶段。不关闭在场/玩家发言/权威事实校验。 |
| 世界前置条件 | WorldBlockedError 给准确限制，合法无发现是正常结果；不交模型改写世界规则。 |
| Core/提交/文件错误 | 不以 LLM 重试整条玩家请求；保留既有候选、Receipt、请求终态与幂等保护。状态不确定时仍使用保守提示和诊断，不能伪装成功。 |
| 后台事件候选 | 复用最多 3 次提案校验循环。Schema 路径现在也能进入该循环；网络/程序异常直接退出，不消耗三份同样请求。玩家合法行动不因补充失败整体失败，沿用持久化冷却。 |

这些是分阶段上限，不是承诺复杂回合总共只调用 2 次。既有低推理目标保真审核的安全回退保留，尚未进行真实成本/P95 验证。

## 4. QA25 / QA26

- 明确多个听众和单个谈话对象使用不同基数契约；不将被谈论人物当听众。
- 群体阶段 → Scene → 听闻/发言记录 → 阅读 Core 活动 → 时间 → 后台系统 → 保存，全部经过原有 HTTP 和事务边界。
- 后续阅读依赖交流时不能越过失败；明确独立的阅读可以执行，并保留未完成交流。修复独立步骤完成时覆盖其他 waiting 状态/问题的断点，避免额外的末尾进度快照遮住行动 Undo。
- 查询目标状态、取消当前目标、查询/取消/恢复目标 UUID、恢复之前目标统一走已有持久化状态。只有明确续接才执行；查询不推进时间或 Revision。
- **paused_goals 原来遗漏在 World Undo 图像之外**，本轮纳入快照与校验。新回合可正确撤回暂停计划的变化。旧快照若从未记录非空暂停集合，不能猜其历史：校验不一致时安全拒绝回溯，不自动迁移或改正式历史。
- 原有请求结果恢复、Save/Reload、重复 request_id、已完成阶段证据复验保留。历史失败响应不被改写成新成功。

## 5. 自主世界的完整生命周期

已有且接入：离散时间钩子、事件概率与阶段、实际效果、NPC 自主 MOVE/INSPECT/TALK/HOLD/物品行为、个人认知、社交任务、曝光、持久化与 Undo。深度 NPC 决策仍按已有频率/预算调度，未通过提高固定模型调用频率制造活跃。

### 本轮确认并修复

1. 启用补充但初始事件池为空时，提前 return，永远不会请求第一个运行时候选。
2. 一条远期 dormant 事件挡住所有独立日常补充：现在在事件容量允许、没有近期种子将占位时，仍可按世界时间冷却评估候选。
3. quiet 在有潜伏主轴且无事件时被拒，容易逼模型无依据造事件：现在 quiet 合法，但冷却后重新评估，既不强制热闹，也不永久安静锁死。
4. 提案只有人物角色和主轴，缺乏 NPC 实际个人目标/行动来源：补入受限、已登记的目标、关系、已提交 NPC Receipt 因果引用；逐个核验存在性及参与者。无父事件/主轴的日常事件必须有实际引用。GM 生成上下文包含既定真相以避免改写，绝不直接投影给玩家。
5. 日常事件不再仅因参与者也出现在主轴中，就自动被挂到主轴。
6. 主轴 incident_refs 仅 10 个，事件历史却允许 100 个，第 11 条后继会结构失败；统一到现有 100 上限，并让新关联事件使已解决主轴回到 developing。
7. Background move_npc 曾直接赋值位置：现走既有 Core MOVE、合法路线/身体约束/时间预算、个人经历与提交 Receipt；使用已经流逝的世界时间，不重复推进玩家时钟。受阻阶段不部分应用效果，也不使正常玩家休息失败。
8. 补充校验包含 Schema 诊断、阶段阻碍原因、active/dormant/候选待处理/容量达到等安全统计。

### 不应当改成 Bug 的情况

前置条件未满足、概率落空、安静决定、玩家错过现场均可能合法。正式世界目前确实有 active 事件、Macro Arc developing 和阶段记录；不能将未感受到剧情归结为“从未运行”，也不应提前触发或新增固定案件。

### 隔离持续运行结果

独立合成世界，玩家 48 次正常休息，每次 60 游戏分钟，覆盖 48 小时；没有“触发剧情”指令。实际通过既有 GameService/Core/存储和 NPC 调度，另由 HTTP 回放覆盖自然阅读入口。

测得：16 次 NPC 决策、12 个事件候选、24 次有效 NPC 行动（MOVE 2、TALK 14、INSPECT 8），每游戏小时 0.5 次；12 条事件结束。玩家不在场时曝光 0，后续到场曝光 12。替身调用共 113 次，真实模型调用 0。Token 不可用；这些数据不能作为真实 Provider 延迟、成本或自然叙事质量结论。

NPC 交流形成双方各自听闻记忆；已提交行动可成为后继事件来源；现场公告能进入之后 NPC 上下文。另测无触发条件、quiet、远期 dormant、取消/结束、无效因果引用、路线受阻和无双重时间。

### 仍有明确边界

- 不是无上限事件社会：现有事件历史总容量 100，达到容量停止补充并记录诊断。**超过容量的长期归档/持续生成未完成**，本轮不另建事件存储系统。
- 不保证模型所有因果解释正确；程序验证引用、人物、位置、时间、效果和既定状态，文学层动机仍需真实模型 QA。
- 已写好的事件使用既有阶段规则；NPC 自主意图不等于必然行动，个人知识仍只来自自身感知、听闻、状态和授权的公开渠道。
- 正式世界没有本轮真实后续游玩证据，不能将隔离模拟成功等同于正式世界已经活跃。

## 7. 用户安全部署与最低成本核验

确认正式没有在途请求后，由用户在**原启动终端**正常停止服务，再执行：

```powershell
Set-Location D:\game
npm run start:lan
```

另一个 PowerShell：

```powershell
(Invoke-RestMethod http://127.0.0.1:3100/api/session).runtime |
  Select-Object version, execution, code_sha256
Get-FileHash D:\game\data\current.json -Algorithm SHA256
```

上述启动不自动执行玩家行动，不调用模型。必须由用户自己正常停旧服务，Codex 未停止/重启进程。

最低成本离线复核（约 20–40 秒，无 API，仅临时隔离状态）：

```powershell
npx vitest run tests/qa25-http-replay.test.ts tests/semantic-understanding-retry.test.ts --maxWorkers=1
```

长期模拟（约 1–2 分钟、0 API）：

```powershell
npx vitest run tests/architecture-world-continuity.test.ts --maxWorkers=1
```

部署后先用“查询目标状态”查看真实计划（只读），再由用户选择是否取消或指定续接；不要自动重试旧失败请求。建议真人 QA：明确的群体告知后阅读、独立日常阅读、普通生活数个世界小时后的可观察变化。失败时保留 request_id/trace_id、runtime 指纹、agent.speech_binding / agent.recovery.decision / scene.response / background_event.*，不要粘贴凭证或完整 GM 数据。
