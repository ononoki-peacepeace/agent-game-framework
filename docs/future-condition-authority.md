# Deferred intent condition authority

Due execution previously evaluated familiarity/presence against the action recipient, even when the player's condition named somebody else. A true condition could therefore be blocked, while a false or unknown condition could execute. Nested future intents retained only the direct condition and lost outer guards. Seven independent reproductions failed before the repair, including old single-condition records and actual Core attempts.

The existing future-intent schema now accepts optional `condition_guards`, a bounded list of `{condition, expected}`. Registration collects the original branch constraints through nested conditions and intermediate dependencies; it does not reinterpret text or invent AND/OR semantics. Execution checks all retained guards and the legacy condition against each condition's own public entity. Unknown, unsupported or currently false checks stop before interpretation or a world action. A prior ELSE preserves expected=false. Existing target availability, front-of-scene checks, action verification and authoritative receipt/commit handling remain.

Old saves without the optional field use the existing `condition`/`condition_expected` fields, now with correct entity ownership. No default migration or production write is required. New records retain the legacy fields as well; an added guard cannot override an old condition. Existing public-fact/observed-event due conditions remain conservative when they cannot be established; this change does not add a model call to prove them.

Integration dependency: ship `src/agent/plan-schema.ts`, `src/agent/future.ts` and `src/agent/executor.ts` together. Core Save validation and public view already derive their types from this schema. The change is additive for the current reader; an older strict-schema binary must be upgraded before it reads new guard-bearing records. No mixed-version deployment is claimed or performed. The Claude worktree and unmerged interfaces are not prerequisites.
