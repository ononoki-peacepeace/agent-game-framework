# v0.1.20 — authoritative actions, recovery and persistent-world integration

This release brings the reviewed development checkpoints through `96133cc` into main, with release preparation on `codex/release-v0.1.20`. It is a source release for local evaluation; no production service was deployed or restarted.

## Main changes

- Integrates four-theme work on request/revision/receipt recovery, natural-language action binding and conditions, NPC knowledge/goals/plans, and fact-constrained narration.
- Preserves actual committed compound steps after lost acknowledgements. Repeated identical actions keep their own execution identity, and narration-only presentation keeps earlier committed prose visible.
- Adds bounded nested-condition HTTP/restart evidence and compound failure/three-world corpora, including partial results and dependent-tail stopping. Core remains authoritative for world results and NPC reactions.
- Retains isolated extension-install/Git-worktree protection and documented recovery boundaries; these do not establish every failure or crash boundary.
- Replaces whole-blob public auditing with streaming metadata and size-framed Git object reads. Tests cover binary blobs larger than 32 MiB under a bounded heap, chunk boundaries, deleted historical paths, invalid references and exact-object exception scope.
- Refreshes the public README and verifies all shipped JSON examples through production input/domain readers. Package and lockfile metadata are 0.1.20.

## Public audit review

The initial reachable-history audit failed on one ordinary Windows user/attachment path in a QA development document. Review found no credential value, attachment contents or personal records in that path. It was already publicly reachable on the integration branch in commit `797ff6ab1a52eaa62c3b3a9506f44e7cb3a5050d` and readable through GitHub's public object API, although not previously in main. The owner explicitly authorized treating this as a low-risk ordinary-path exception. The current document is sanitized; the exact historical blob and review reason remain visible in `docs/public-audit-exceptions.json`. No history rewrite or force push occurred. Other objects, credentials, private keys and credential URLs are not excepted.

Run the publication audit with `node scripts/audit-public.mjs --revision HEAD --exceptions docs/public-audit-exceptions.json`. It scans the candidate tree, deleted historical paths and all reachable objects, reporting active findings separately from approved exceptions. It is a heuristic with a bounded 64 KiB overlap, not a comprehensive guarantee against every private-data format.
