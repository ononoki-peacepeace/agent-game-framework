# Verify existing content-addressed image bytes before binding

Parent `8cf0712`, product `396d1be`: ImageAssetRuntime treated `EEXIST` as proof that its generated content-addressed file was valid. A truncated file or different bytes at that path therefore returned a successful artifact and the service bound the broken image. Original offline baseline: two failures, two valid new/existing controls passed. Reports are retained.

The duplicate-file path now reads the existing bytes and compares them with the validated generated bytes. A mismatch fails explicitly before binding, retaining the existing file as evidence. Real isolated JsonStore tests confirm the save's bytes, revision and state remain unchanged. Valid new assets and identical existing bytes still succeed. This does not regenerate, overwrite, delete or repair the damaged asset, and it does not add a provider retry.

Final isolated regression: **five files, 42/42 passed, zero skips**; full isolated build passed (session 8834). Tests use a fixed offline PNG/provider and include existing media/canonical/recovery and two-service migration controls. No paid provider or formal service/data is used. Failure and final evidence are retained under ignored takeover `image-existing-content-*`.

Only `src/media/image.ts` changes in the product. No schema, save contract, request identity, service signature or model budget changes. External mutation after checking, atomic creation/crash recovery, request-level provider deduplication and reference-aware garbage collection remain outside this fix. R8.3 stays unmet; **97/160, 60.625% (60.63%), net zero**. Latest complete snapshot stays `fa53def` / evidence `5ec89d6` (238 files / 2371 assertions); later products have targeted evidence only.
