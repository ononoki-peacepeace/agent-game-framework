# Behavior guidance: mutation identity and scope

World guidance now uses the existing Save receipt, revision and `prepareRequestCommit` protocol. `putBehaviorPatch` accepts an optional request envelope and an internal original-source argument; `removeBehaviorPatch` and `setBehaviorPatchEnabled` accept an optional envelope plus `scope`. World writes validate and prepare before one Save write. Receipt replay precedes target lookup and revision rejection, so a deleted guidance row can still replay its original removal without deleting a later state. These are configuration edits, without a world turn or new action resolution.

System feedback forwards the original request ID/game/revision and exact user text. `recoverSystemConfigurationRequest` checks style or world-guidance receipts before semantic routing or model compilation, including after restart. The older `recoverBehaviorConfigRequest` remains a style-only compatibility wrapper. Direct structured calls bind their complete operation; the internal source-text identity is supplied by the server, not model output or a new HTTP field.

Guidance IDs are no longer silently moved between persistence scopes. An unscoped operation resolves only a unique ID. Legacy duplicates across scopes fail before any write; an explicitly scoped operation changes only that scope. This avoids the old world-save → global-file → session sequence and its partial deletion on a later failure. It does not pretend that separate files form one atomic transaction. Existing callers with unique IDs remain supported. The frontend sends scope and a request envelope; HTTP enabled values must be actual booleans.

Global guidance retains its existing array file format and uses the shared atomic JSON writer. After a global write throws, the service re-reads disk authority before publishing cached guidance. If the read also fails, the cache is invalidated and subsequent service reads retry or fail, instead of knowingly serving stale values. Concurrent initialization shares one pending read. No write/model call is retried by this recovery. A retained System feedback ID with the same source reuses its existing patch, including a later disabled state; self-overrides are rejected.

Identified global/session changes now journal intent and terminal identity using the existing atomic `StoredInputRecord` storage. A deterministic namespaced child UUID keeps this record separate from `/api/input`'s parent; the record validates its marker, original request identity and operation/source fingerprint. It does not write a second world image or claim cross-file atomicity. A completed request replays before target lookup, even after its rule is removed; a failed result retains its error and forbids effect replay. A running record without a live operation stops conservatively. System source-text lookup precedes model work. Concurrent System lookup waits for the same service's live operation before reading the result. Changed arguments or foreign records fail before mutation.

Intent flush failure stops effects. Effect failure may have saved the global file; the existing disk-authority cache reconciliation is retained. Terminal flush failure never overwrites a possibly completed record with failure: restart sees either the completed record or an uncertain intent, and neither repeats the effect. HTTP errors carry `do_not_replay`; `/api/input` cannot infer unchanged global/session state from unchanged world revision. Session content remains process-local: replaying its old identity does not restore a prior session's rules. Legacy calls without a request ID remain compatible but have no new durable identity guarantee. Identified mutations require a storage implementation supporting the existing journal methods.

Limitations remain explicit: global/session changes do not acquire a world receipt. Multi-process/global-file locking and cross-scope moves remain open. Process recreation tests use real temporary JsonStore files, not OS power-loss or process-kill evidence. Journal/record garbage collection and external writers are not solved by this batch. A retained uncertain intent deliberately requires inspection instead of automatic mutation replay.

Integrate service, System feedback/compiler, HTTP routes and frontend together. Storage interface and Save schema are unchanged.
