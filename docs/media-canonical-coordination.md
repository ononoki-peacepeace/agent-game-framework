# Media and canonical save coordination

The canonical mutation flag and presentation queue protected different writers. Several short configuration operations read a complete save outside the presentation queue and later overwrote a concurrent avatar; the reverse order lost configuration. An in-flight avatar could also write an old game back after new-game/load/import completed. Idle migration persistence had the same media crossing despite its canonical lock.

Short local mutations now acquire the existing canonical lock, then the existing presentation queue before reading and committing: style/preferences/guidance, calendar, module lifecycle, declared activity, story commands and clarification metadata. A media-first operation may advance revision, so a queued stale configuration receives the normal revision conflict; it cannot claim success and disappear. New-game/load/import take the presentation queue only for their final replacement write. Initialization/model generation remains outside that queue.

Avatar/fullbody writes already own the presentation queue. `presentationCurrent` therefore performs deterministic normalization in the returned snapshot and persists it with the media write, avoiding recursive queue acquisition during idle migration. This also keeps media usable under a routine lease. No reentrant queue protocol or lock ownership schema was added.

Long world turns retain their existing behavior: media can commit while narration/model work is pending, and the final world commit merges current presentation. The parent request intent now records `next.state_revision - 1`, the actual predecessor of the receipt after that merge. Using the original pre-narration revision failed `committedInputReceipts` when media had advanced the revision. The fix changes no action outcome, RNG, time cost or receipt fingerprint, and never reruns the action.

The pre-fix `media-canonical-baseline.json` records 19 real failures: both write orders across seven short mutation paths, three world replacements, idle migration and receipt recovery during narration. The expanded isolated regression passed 134 tests across fourteen files, including actual HTTP input failure and durable duplicate replay after disk/service restart. Media remained usable during blocked narration and under a routine lease. Exact later Core/Narrator regression and type-check results are in the handoff.

Limits: this is single-service coordination for the listed storage paths. It does not establish cross-process locking, external media garbage collection, paid-provider response deduplication, arbitrary external SaveStorage writers or OS-crash durability. Existing bounded receipt eviction remains. No production save, provider, port 3100 or deployment was changed.
