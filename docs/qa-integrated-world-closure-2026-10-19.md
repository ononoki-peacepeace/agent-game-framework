# Agent Game Framework 有边界收口（2026-10-19）

本报告将新 Framework 代码、正式旧存档迁移和真人游戏验收分为三个独立门禁。没有执行付费游戏 Provider、正式玩家行动、正式存档写入或部署。工作树包含接管前的未提交成果；没有重置、清理、覆盖或删除备份。

## 容器完整范围与关键 A–O

- 容器普通概览仍最多确认三项，不表示穷尽。玩家明确彻底检查后，AI 可提出完整空范围，或非空容器的完整内容清单及“无其他普通内容物”的独立依据。依据须逐字绑定当前权威世界或场景；无依据先有界修正，Core 再核对授权、每件内容的客观实体和既有裁决、数量上限及隐藏证据。漏列已有内容时不登记完整范围。
- 后续完整检查可在旧概览之后追加有顺序的检查记录。完整范围只排除检查时没有的内容，不抹掉过去记录。新的具名查询复用已登记内容；未列项目登记历史缺席。只有后来真实 Core 放入动作产生更晚 `placed_sequence`，才能使旧缺席不再代表当前位置。重放、Undo、并发检查不复制事实。
- 玩家公开投影不再提前列出尚未发现的场景容器内容物。明确检查可发现同一已存在的普通物品并登记玩家可见性，不会复制它；受保护证据、封存物和他人私有物仍不能借此暴露。旧完整检查之后若出现不可公开的内容，重复检查既不泄露名称，也不虚称当前仍完整为空。
- A–D 的房间概览、局部目标有无、NPC 私有发现继续由既有定向用例覆盖。E 新增非空完整范围、漏列阻断、旧缺席和后放入验收。I 的有证据开局修复及原行动续行、J 的三人通知后阅读故障恢复、M 的 NPC 陈旧认知继续通过既有用例。N 新增场景容器内容的投影遮蔽与明确检查后发现测试。O 新增服务层完整范围重放/Undo及同 revision 并发概览单实例测试。H 的受保护事实未放宽；K/L 的候选修正新增完整范围伪造依据用例。
- F/G 的通用资源类别与更长自治链、N 的全部辅助 API/界面隐私出口、K/L 的所有辅助失败出口，仍没有声称全覆盖；现有保护和离线回归不能替代真人模型验收。

## 旧档安全裁决与迁移流程

1. 自动修复只接受现有结构化权威证据：零回合完整开局物品账本，或有效最近 Undo 前像证明持有且随后没有物品/装备效果；还必须验证唯一 ID、所有权、放置关系和原玩家动作的原子提交/重放/Undo。`repairOpeningPossessionsForAction` 已覆盖这两类条件。不从职业、回忆或叙事补发。
2. 对正式 revision 389，逐件列为人工确认：相机是否仍存在、当前持有者和位置；胶卷/胶片数量与是否已装入相机；外套是否还在及是否穿戴。确认须依赖可核验的外部完整历史或玩家/维护者明确的当前状态裁决，并保存来源、裁决者、时间与逐件结论。无法确认的物品保持未决，可通过正常游戏中的合法取得途径继续，不写入背包。
3. 经人工裁决后，另行准备可审阅的迁移候选差异。执行前再次读取正式存档并锁定 revision 与 SHA-256，检查全世界同名/同 ID 实体、所有背包、装备、场景及近期 receipt。若冲突或正式档已前进，重新裁决。只在现有事务/检查点中一次性提交已确认物品，校验 Schema、receipt、重放和 Undo；不直接编辑 JSON，不根据旁白填写装备槽或胶卷装载关系。本轮没有执行迁移。
4. 旧的 `qa-initial-possessions-migration-preview.md` 基于 revision 260，不能直接执行。当前只读校验 revision **389**，SHA-256 `119585428f0739a55865f97a1372879007bfdfc6893e10edb42179f42b60b75c`，Schema 有效且检查前后字节未变。
